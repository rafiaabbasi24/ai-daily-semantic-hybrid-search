## Project Overview
The **Multilingual Hybrid Semantic Search API** provides a high‑performance, language‑agnostic search service that combines dense vector similarity (via Transformer‑based embeddings) with traditional sparse lexical matching (via TF‑IDF). It is designed for production environments where low latency, scalability, and multilingual support (over 100 languages) are essential.

Key use‑cases include:
- Enterprise document retrieval across multilingual corpora
- Knowledge‑base question answering
- E‑commerce product search with multilingual catalogs
- Academic literature discovery

The API is built with **FastAPI**, leveraging **PyTorch**, **Transformers**, **SentenceTransformers**, and **scikit‑learn** for the core retrieval logic.

---

## Features
- **Multilingual embeddings** using pre‑trained multilingual Sentence‑BERT models.
- **Hybrid retrieval**: dense vector similarity + sparse TF‑IDF scoring.
- **Dynamic indexing**: add, update, or delete documents without service downtime.
- **Batch ingestion** for large corpora.
- **RESTful endpoints** with OpenAPI documentation automatically generated by FastAPI.
- **GPU acceleration** (optional) for embedding generation.
- **Configurable similarity metrics** (cosine, dot product, Euclidean).
- **Built‑in caching** with `functools.lru_cache` for repeated queries.
- **Dockerized** for reproducible deployments.

## Architecture
```
┌─────────────────────┐
│   FastAPI (HTTP)    │
│   /search, /index   │
└─────────┬───────────┘
          │
   ┌──────▼───────┐
   │   Service    │
   │   Layer      │
   └──────┬───────┘
          │
   ┌──────▼───────────────────────┐
   │   Retrieval Engine            │
   │   • SentenceTransformer embedder│
   │   • Scikit‑learn TF‑IDF vectorizer│
   │   • Hybrid scoring module      │
   └──────┬───────────────────────┘
          │
   ┌──────▼───────┐
   │   Vector DB  │
   │   (FAISS /   │
   │   Annoy)     │
   └──────┬───────┘
          │
   ┌──────▼───────┐
   │   Persistent │
   │   Store (PG) │
   └──────────────┘
```

- **FastAPI** handles request routing, validation, and OpenAPI docs.
- **Retrieval Engine** computes dense embeddings, builds a sparse TF‑IDF matrix, and merges scores.
- **Vector DB** (FAISS) stores dense vectors for efficient ANN search.
- **PostgreSQL** (or any relational DB) persists raw documents and metadata.

## Configuration
Configuration is driven by environment variables. Create a `.env` file in the project root (or set variables in your deployment environment).

```dotenv
# Server
HOST=0.0.0.0
PORT=8000

# Model
MODEL_NAME=sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
USE_GPU=true   # set to false to force CPU

# FAISS
FAISS_INDEX_PATH=./data/faiss.index
FAISS_DIM=384   # must match embedding dimension of the chosen model

# Sparse retrieval
TFIDF_MAX_FEATURES=50000

# Database (optional)
POSTGRES_DSN=postgresql://user:password@localhost:5432/searchdb

# Logging
LOG_LEVEL=info
```

The application loads the configuration via `pydantic.BaseSettings` (see `app/config.py`).

## Running the Service

### Development (auto‑reload)
```bash
uvicorn app.main:app --host $HOST --port $PORT --reload
```

### Production (Gunicorn + Uvicorn workers)
```bash
gunicorn app.main:app \
  -w 4 -k uvicorn.workers.UvicornWorker \
  --bind $HOST:$PORT \
  --log-level $LOG_LEVEL
```

### Docker
```bash
docker build -t multilingual-semsearch .
docker run -d -p 8000:8000 --env-file .env multilingual-semsearch
```

The OpenAPI UI is available at `http://localhost:8000/docs`.

## API Reference

### 1. Index Documents
**Endpoint:** `POST /index`  
**Description:** Add or update a batch of documents.

**Request Body (JSON)**
```json
{
  "documents": [
    {
      "id": "doc-123",
      "title": "Einführung in die Quantenphysik",
      "content": "Die Quantenphysik beschreibt ...",
      "metadata": {"category": "science", "lang": "de"}
    },
    {
      "id": "doc-124",
      "title": "Introduction to Quantum Physics",
      "content": "Quantum physics deals with ...",
      "metadata": {"category": "science", "lang": "en"}
    }
  ]
}
```

**Response**
- `200 OK` – indexing succeeded.
- `400 Bad Request` – validation errors.

### 2. Delete Document
**Endpoint:** `DELETE /document/{doc_id}`  
**Response:** `204 No Content` on success.

### 3. Search
**Endpoint:** `POST /search`  
**Description:** Perform a hybrid search over indexed documents.

**Request Body**
```json
{
  "query": "What is quantum entanglement?",
  "top_k": 10,
  "filters": {
    "lang": ["en", "de"],
    "category": "science"
  },
  "use_dense": true,
  "use_sparse": true,
  "alpha": 0.7   // weight of dense score (0‑1)
}
```

**Response**
```json
{
  "results": [
    {
      "id": "doc-124",
      "title": "Introduction to Quantum Physics",
      "score": 0.92,
      "metadata": {"category": "science", "lang": "en"}
    },
    {
      "id": "doc-123",
      "title": "Einführung in die Quantenphysik",
      "score": 0.88,
      "metadata": {"category": "science", "lang": "de"}
    }
  ]
}
```

### 4. Health Check
**Endpoint:** `GET /health` – returns `200 OK` with JSON `{ "status": "healthy" }`.

All request/response models are defined in `app/schemas.py` and validated with Pydantic v2.

## Testing

### Unit & Integration Tests
```bash
pytest -vv
```

The test suite covers:
- Model loading and device selection
- Embedding generation correctness (sanity checks against known vectors)
- FAISS index creation, add, and search
- TF‑IDF vectorizer consistency
- Hybrid scoring logic
- FastAPI endpoint validation (using `httpx.AsyncClient`)

### Example Test Snippet (`tests/test_search.py`)
```python
import pytest
from httpx import AsyncClient
from app.main import app

@pytest.mark.asyncio
async def test_hybrid_search_returns_expected_fields():
    async with AsyncClient(app=app, base_url="http://test") as client:
        # Index a minimal document
        await client.post("/index", json={
            "documents": [{
                "id": "doc-test",
                "title": "Test Document",
                "content": "FastAPI is awesome.",
                "metadata": {"lang": "en"}
            }]
        })
        # Perform search
        resp = await client.post("/search", json={
            "query": "What is FastAPI?",
            "top_k": 1,
            "use_dense": True,
            "use_sparse": True,
            "alpha": 0.5
        })
        assert resp.status_code == 200
        data = resp.json()
        assert "results" in data
        assert len(data["results"]) == 1
        result = data["results"][0]
        assert result["id"] == "doc-test"
        assert isinstance(result["score"], float)
```

Run tests in CI with GitHub Actions (see `.github/workflows/ci.yml`).

## Performance & Scaling

| Component | Scaling Strategy |
|-----------|------------------|
| **FastAPI** | Deploy multiple workers (Gunicorn) behind a load balancer. |
| **FAISS** | Use `faiss.IndexIVFFlat` or `faiss.IndexHNSW` for larger corpora; shard across multiple nodes if >10M vectors. |
| **GPU** | Switch to `faiss-gpu` and enable `torch.cuda.is_available()` for embedding inference. |
| **Cache** | LRU cache for recent query embeddings; optional Redis for distributed caching. |
| **Batching** | The `/index` endpoint accepts bulk payloads (up to 10 k docs) to amortize model loading cost. |

Monitoring:
- Export Prometheus metrics via `fastapi_prometheus`.
- Log request latency and error rates with structured JSON logs.

## Deployment

### Docker Compose (local stack)
```yaml
version: "3.9"
services:
  api:
    build: .
    ports:
      - "8000:8000"
    env_file: .env
    depends_on:
      - postgres
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: searchdb
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:
```

### Kubernetes (helm chart)
A minimal Helm chart is provided under `helm/`. Key values:
```yaml
replicaCount: 3
image:
  repository: your-registry/multilingual-semsearch
  tag: latest
resources:
  limits:
    cpu: "2000m"
    memory: "4Gi"
  requests:
    cpu: "500m"
    memory: "1Gi"
service:
  type: LoadBalancer
  port: 80
```

### CI/CD
- **GitHub Actions** runs linting (`ruff`), type checking (`mypy`), and tests on every push.
- Docker image is built and pushed to the registry on successful merges to `main`.
